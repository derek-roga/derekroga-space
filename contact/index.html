What to write about

Derek builds small tools and writes about front-end development and print tooling, so most messages fall into a few kinds. Feedback on TestPrintPage is welcome: a sheet that printed wrong, a symptom the guides do not cover, or a printer the sheets do not handle well. Questions about the printer guides are welcome too, especially when a guide's steps did not match what the printer did. The same goes for Volume Booster and for the essays on this site: if something is unclear, or if a step is missing, saying so helps the next reader as much as it helps you. Consulting enquiries about Web3 work are welcome as well; the consulting page sets out what is verified about that work. If you are not sure which kind your message is, any profile will do; the message matters more than the route.

Which profile to use

The profiles above all reach the same person, but some fit some messages better than others. GitHub is the natural place for anything about code: a bug in a tool, a suggestion, or a question with a technical answer. Dev.to and Hashnode fit discussion about the writing: a comment on an essay, a disagreement, or a follow-up question. X and Bluesky fit short messages and quick questions. The remaining profiles are pages rather than inboxes, so for a message, start with one of the five named above. A message that says what you tried, and what happened, gets a better answer than one that only says something is broken.

Email and privacy

There is no public email address on this site, and no contact form. The profiles above are the way to reach Derek.

This site collects no personal data directly. What it does collect, through its analytics, is set out on the Privacy page.
